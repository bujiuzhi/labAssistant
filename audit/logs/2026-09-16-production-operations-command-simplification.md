# 2026-09-16 生产运维命令收敛

## 决策

将首次部署、日常重启和停用服务收敛为 `install`、`restart`、`uninstall` 三个生产脚本入口；已有 `upgrade` 继续作为后续发布的单命令入口。脚本内部保留 Compose、发布清单、空库初始化、升级备份和健康检查，不以直接 `docker compose up -d` 替代关键校验。

## 影响与安全边界

`install` 仅适用于空库：生成不存在的密钥目录、准备持久目录、构建不可变镜像、初始化并启动。`restart` 仅停止和启动 API/Web。`uninstall` 仅执行本项目 Compose 容器和网络移除，明确保留 PostgreSQL、RustFS、备份、发布清单、密钥和镜像。

不提供自动删库、删备份或覆盖已有数据能力；完整数据清除仍需先创建恢复组、明确确认目标目录并执行受控操作。

## 验证与恢复

新增隔离运维测试覆盖首次单命令部署、重启和保留数据的卸载语义。脚本语法和运维测试通过后，首次部署可使用 `install`，已有环境升级继续使用 `upgrade`。若 `install` 或 `upgrade` 失败，现有启动失败处理会停止 API/Web 写入口，持久数据和恢复组保留。
