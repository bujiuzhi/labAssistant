## 决策与兼容性

新增 `scripts/deploy.sh` 常用入口，复用 `production.sh`。新模板仅保留端口、管理员登录名和显示名；目录按 HOME 推导，密码随机生成，发布标签由提交前缀、时间与进程号生成，清单记录完整 SHA/镜像 ID。

已有完整 `MATERIALS_LAB_*` 配置不迁移、不覆盖、不改变路径或密钥。完整模板保留为 `infra/.env.production.full.example`；旧配置仍先设置显式标签并构建后升级。

`active.env` 固定当前版本，避免拉取代码后重启意外升级。上线前记录 `incomplete.env`，失败阻断旧镜像隐式启动；`resume` 只继续目标版本启动，不重做初始化或自动降级数据库。变更操作复用底层共享锁。

自动 Host 模式校验实际转发的 `$http_host`，只接受有效 IPv4 与端口；固定 IP 模式兼容。HTTP 明文边界未改变，文档保留可信来源限制要求。

## 独立审查与修复

| 问题 | 修复 |
| --- | --- |
| 升级失败后重启可能隐式回退不兼容旧代码 | 失败标记、目标版本 resume、锁内复查 |
| 校验 Host 与实际转发 Host 不一致 | 自动模式直接校验 `$http_host` |
| 部分镜像构建成功后标签不可覆盖阻碍重试 | 每次构建独立标签，不改变不可覆盖规则 |

独立只读复审未发现新增重大问题。按复审补充：仅进入停写阶段后的失败保证保持停写；resume 不替代未成功的 bootstrap。
