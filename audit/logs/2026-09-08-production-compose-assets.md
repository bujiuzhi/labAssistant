## 📦 决策与实现

生产与开发 Compose 完全分离。生产仅运行 PostgreSQL、Java API 和 Nginx 静态 Web，
不加入当前业务未使用的 Redis/RustFS。默认直接 TLS，也支持经明确确认的同机 HTTPS 上游。
数据限定项目专属目录，API/数据库不发布宿主端口；API/Web 非 root、只读根文件系统。

生产应用库由非超级用户持有以运行 Flyway；数据库超级用户、应用及首个管理员分别使用独立文件 Secret。
正常 API 不自动建账。显式一次性 bootstrap 仅创建真实组织、管理员、三个角色和现有权限，
拒绝保留的开发组织代码、非项目数据库对象、已有业务数据和重复初始化。
开发与生产共用 RBAC/BCrypt 定义，不扩大原有角色权限，不新增业务表或修改已执行迁移。

运维入口提供预检、构建、初始化、启动、升级、备份、空库恢复及明确兼容前提下的应用回退。
升级停写后先备份；失败尝试再次停止 API/Web，保留数据库及故障证据。
备份包含原始文档正文、SHA-256 和实际来源容器镜像/Flyway 元数据，不用目标发布标签冒充来源。
不实现删库、删卷、覆盖已有数据、自动数据库降级或自动资源清理。

2026-09-08 12:00:00（Asia/Shanghai）补充正式发布边界：运行时 Compose 移除 `build` 定义，
`up`、`upgrade`、`rollback` 均只使用已存在的同标签镜像；受控构建由脚本直接调用 Dockerfile 完成。
构建标签不可覆盖，交付前须记录镜像 ID/摘要并通过受控仓库或离线导入分发，避免目标运行服务器从未审查工作区源码构建。

prod 明确 Secure Cookie、20 MiB 文件/22 MiB 请求限额、数据库会话上海时区；Compose 配置容器/JVM和数据库服务上海时区。
`/health/ready` 增加 Spring 接受流量状态门禁，全部启动任务（含迁移）完成后才探测数据库并返回 200。
启动未就绪返回 503 与 `data.application=not_ready`，成功响应不变，OpenAPI 和现行文档同步更新。

正式操作入口：[生产部署指南](../../docs/production-deployment.md)。

## 🔍 审查及修复

由未参与实现的代理独立阅读实际源码/差异，主代理复核并修复，最终限定范围内无剩余重大问题。

| 问题 | 处理与验证 |
| --- | --- |
| 上线失败仍可能留写入口运行 | EXIT 失败处理停 Web/API，失败注入及停服失败路径覆盖 |
| 容器状态只判断 running，或列表失败被当作空 | 明确仅接受 created/exited，ps/inspect 失败立即中止 |
| 空库判断漏其他 schema/关系 | 检查非系统 schema 和 public 预期关系，锁表后二次核查数据 |
| DEV_TEST 提交后才被脚本拒绝 | 初始化参数阶段大小写不敏感拒绝 |
| 备份版本取自目标标签 | 改为实际源容器镜像引用/ID 与迁移历史元数据 |
| 数据库可连但迁移未完成即就绪 | 使用 ApplicationAvailability 门禁并增加 5 个测试 |
| Bash 3.2 中文紧邻变量导致异常退出假成功 | 明确变量边界，未完成上线退出即按失败处理，增加回归 |
| tmpfs 内联 YAML 逗号拆分 | 挂载字符串整体加引号，增加静态回归及真实启动验证 |
| PostgreSQL 系统目录 char 拼接歧义 | 显式转 text；真实 PostgreSQL 初始化及恢复通过 |
