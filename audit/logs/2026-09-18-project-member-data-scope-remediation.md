# 2026-09-18 项目成员数据范围修复

记录时间：2026-09-18（Asia/Shanghai）
仓库与分支：`labAssistant` / `dev`
范围：项目创建/编辑的成员持久化、项目详情成员编辑入口及现有本机成员关系补正

## 问题与决策

- 项目创建页面和详情编辑请求会提交 `member_ids`，但后端此前没有将其写入 `project_member`；详情页又引用了不存在的 `project.manage_members` 权限码，导致成员编辑控件永久隐藏。
- 实验员虽拥有 `project.read`、`document.view` 和 `experiment.read` 等动作权限，但缺少项目成员关系时会被项目和实验查询的数据范围条件拒绝。这是授权模型的预期保护，不应改为放宽全组织访问。
- 创建时及 PATCH 显式提供 `member_ids` 时，服务端现在在同一事务内校验成员均为当前组织的有效账号，并同步为普通 `researcher` 项目成员。PATCH 未提供该字段时保留既有成员，空数组仅清除普通成员。
- 项目负责人仍经 `owner_id` 获得访问范围，创建者已有的 `manager` 关系不会被普通成员同步删除；成员同步不授予项目管理权限。

## 数据修复与恢复边界

本次代码升级后，仅对用户已确认的本机项目与对应实验员补写一条普通 `researcher` 项目成员关系；不更改项目负责人、组织角色、实验负责人、附件或其他项目成员。升级前由生产脚本创建恢复组；若需撤销，可在同一项目中删除该普通成员关系，或按恢复组在隔离空环境执行 `restore-new`。
