# 2026-09-17 OCR 生产运行与对象存储修复

记录时间：2026-09-17 11:19:57（Asia/Shanghai）

## 决策与影响

对已确认的生产运行与文件存储风险实施以下修复：

- 为会改动运行、备份或恢复状态的生产脚本命令增加项目级互斥锁；并拒绝将密钥目录放入数据根目录，避免密钥进入 RustFS 数据归档。
- 备份与恢复前要求 RustFS 已停止；备份会停止 RustFS 后再归档其数据目录，升级和应用回退会在启动 API 前恢复 RustFS。恢复前校验归档成员仅位于 `rustfs/data`，并拒绝路径穿越、链接与特殊文件。
- 对象存储每次就绪检查均实际探测桶；读取、删除历史对象时按数据库中保存的桶名而非当前配置桶名定位。
- 文件元数据事务未提交时清理已上传的 RustFS 对象；上传内容校验补充 Office/ODF 容器标识与严格 UTF-8 检查。
- 后续 OCR 复审确认 ZIP/ODF 容器仍需限制解析成本：现限制 Office ZIP 条目数量、跳过的单条元数据大小及 ODF `mimetype` 正文长度，并将旧 Office 标识匹配改为线性算法；同时覆盖硬链接归档拒绝与 RustFS 未停止时拒绝恢复。

上述变更不修改数据库结构、不删除任何数据，也未部署或重启本机/远程生产服务。公网 HTTP、不带 Secure Cookie 的已知风险保持不变，因为当前部署边界明确采用无 TLS 的 IP 加端口访问。
