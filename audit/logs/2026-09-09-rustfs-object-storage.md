# RustFS 文件存储接入记录

时间：2026-09-09 14:25:00（Asia/Shanghai）

## 决策与影响

- 新上传的项目文档、实验过程图片和结果附件通过 RustFS 的 S3 兼容接口保存；PostgreSQL 只保留元数据、权限关联、对象标识和 ELN 正文。
- Redis 保持未接入，不用于缓存、会话或文件传输。
- 对象键由组织、项目或实验 UUID 和文件 UUID 构成，不包含原始文件名；文件仍经 API 完成权限校验后读取，不下发公开对象地址。
- V2 不删除历史 BYTEA 内容表。旧记录继续通过数据库兼容读取，后续迁移旧对象必须先核验数据量、对象清单、校验值和恢复演练。

## 恢复与验证边界

- RustFS 挂载目录和对象清单必须与 PostgreSQL 逻辑备份作为同一恢复点保留；后续生产恢复组整改已使脚本同时生成 PostgreSQL 与 RustFS 数据归档、校验值和架构标识，具体流程以 `2026-09-09-rustfs-production-recovery.md` 为准。
- 已通过 Java 25 Maven 单元测试（53 项）及生产运维脚本隔离测试（35 项）。未连接真实 RustFS、未执行真实生产部署、未迁移既有 BYTEA 对象。
