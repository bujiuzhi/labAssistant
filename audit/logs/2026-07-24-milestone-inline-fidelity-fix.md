# 里程碑内联编辑保真修复记录

## 1. 问题

项目详情页虽然已经具备里程碑新增、修改、删除和保存能力，但入口与基础信息编辑按钮同名，
编辑界面使用居中弹窗。原型 `项目数据/project-detail.js` 和 `project-detail.css` 的实际行为是：
项目里程碑卡片原位切换为编辑状态，卡片头部同时显示说明、取消和保存操作。

因此原实现只能判定为“功能已接通”，不能判定为“与原型一致”。

## 2. 变更资产

| 资产 | 变更 |
|---|---|
| `frontend/src/views/projects/ProjectDetailView.vue` | 将里程碑弹窗改为卡片内联编辑，保留新增、删除、日期、状态、校验和持久化能力 |
| `frontend/src/main.ts` | 在安装路由前恢复 Cookie 会话，避免详情页刷新后误跳登录页 |
| `docs/12-prototype-fidelity-ledger.md` | 登记差异和浏览器验收状态 |

本次不新增或删除数据表、字段、迁移和后端接口。

## 3. 验收路径

1. 管理员登录后进入 `PRJ-2026-PI-005` 项目详情。
2. 点击“项目里程碑”卡片右上角“编辑”。
3. 确认卡片原位出现“编辑项目里程碑”、说明、取消、保存、编辑行和“新增里程碑”。
4. 验证新增行、删除行和取消不写入数据。
5. 保存已有里程碑后刷新详情页，确认三条数据仍存在。
6. 直接刷新详情 URL，确认 Cookie 会话被恢复且不跳转登录页。

## 4. 结论口径

完成上述浏览器回归后，只声明“项目详情里程碑编辑已与原型交互一致”。
其他页面或其他项目详情模块未经逐项浏览器对照时，不声明全站与原型完全一致。

## 5. 执行结果

- 远程前端 `vue-tsc -b && vite build` 通过。
- 详情 URL 直接刷新后仍停留在项目详情，Cookie 会话恢复正常。
- 浏览器实际识别到 2 个编辑入口；点击项目里程碑卡片入口后，卡片原位切换为编辑状态，页面中不存在里程碑弹窗。
- 新增里程碑后编辑行由 3 行变为 4 行，删除后恢复为 3 行；取消后退出编辑态。
- 保存成功后出现“项目里程碑已更新”，再次直接刷新页面，三条里程碑名称各出现 1 次。
- 浏览器截图已核对查看态和编辑态，无空白页、遮罩残留或控件重叠。
