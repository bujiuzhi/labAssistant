# 产品范围与需求基线

## 1. 产品定位

材料实验助手服务于材料研发团队，以项目为数据隔离和协作边界，以实验为核心业务对象，以电子实验记录本为过程证据，以检测结果和报告为归档产物。

目标闭环：

```text
创建项目
→ 创建实验计划
→ 配置配方与工艺步骤
→ 执行并记录实验
→ 生成送检信息
→ 上传检测结果
→ 自动判定与生成报告
→ 归档实验
```

首期定位为桌面优先的独立 Web 应用，不包含 Electron、玄鉴历史会话、技能广场等宿主客户端能力。

## 2. 目标与非目标

### 2.1 首期目标

- 建立项目、成员、实验和文件的服务端数据权限。
- 完成实验计划、配方、工艺步骤和执行记录闭环。
- 支持实验图片、附件、谱图和检测报告的受控上传。
- 支持检测值与标准范围的自动判定。
- 生成可追溯的标准化 PDF 报告。
- 对关键业务操作保存审计记录。
- 支持临期、超时和任务完成提醒。
- 支持管理员维护用户、材料和基础字典。

### 2.2 首期非目标

- 不实现复杂多租户计费。
- 不实现实时多人共同编辑同一 ELN。
- 不实现原生桌面能力和离线桌面数据库。
- 不实现 AI 谱图解析和模型训练。
- 不实现复杂关键路径算法和资源平衡甘特图。
- 不强制第三方检测实验室进入系统。
- 不实现移动端完整实验计划编辑器。

## 3. 用户角色

同一用户可以具有多个组织级或项目级角色。

| 角色代码 | 中文名称 | 作用范围 | 主要职责 |
|---|---|---|---|
| `system_admin` | 系统管理员 | 组织级 | 用户、角色、材料库、基础字典、系统审计 |
| `project_manager` | 项目负责人 | 所负责项目 | 项目、成员、实验计划、进度、复核和归档 |
| `researcher` | 研究人员 | 参与项目及分配实验 | 创建或执行实验、记录过程、发起检测委托 |
| `inspector` | 检测人员 | 分配的检测任务 | 接收检测任务、录入或复核检测结果 |

角色不等同于数据范围。实际权限由“角色权限 + 项目成员关系 + 资源状态”共同决定。

## 4. 核心业务对象

| 对象 | 定义 | 关键边界 |
|---|---|---|
| 组织 | 用户和基础数据的顶级隔离空间 | 首期可只部署一个组织，但表结构保留 `organization_id` |
| 项目 | 成员、实验、文档、数据和里程碑的协作边界 | 项目外用户默认不可读取 |
| 实验 | 一次可计划、执行、检测和归档的研发活动 | 必须属于一个项目 |
| 工艺步骤 | 实验计划中的有序操作单元 | 计划和实际执行数据分离 |
| ELN | 实验执行事实、现象、结果和附件 | 归档版本不可覆盖 |
| 检测委托 | 样品、检测项目和检测标准的集合 | 内部检测由检测人员处理；第三方结果代录规则待确认 |
| 报告 | 由实验、检测结果和模板生成的 PDF 产物 | 生成过程异步，文件带哈希和版本 |

## 5. MVP 功能范围

### 5.1 系统基础

- 账号登录、退出、禁用和密码重置。
- 多角色用户进入系统后显示其可用工作台。
- 组织级和项目级权限隔离。
- 统一字典、审计、请求追踪和错误处理。

### 5.2 工作台

- 研究人员查看今日待办、临期步骤和超时步骤。
- 检测人员查看待接收、待录入和待审核检测任务。
- 项目负责人查看项目进度、实验状态、里程碑风险和待复核事项。
- 系统管理员查看用户、存储、异步任务和异常概况。

### 5.3 项目中心

- 新建、编辑、查看、完成和归档项目。
- 管理项目负责人和项目成员。
- 管理项目里程碑。
- 查看项目实验列表及状态统计。
- 根据名称、编号、类型、负责人和状态筛选。

### 5.4 实验管理

- 创建实验草稿并关联项目。
- 配置实验类型、目的、计划时间、负责人和参与人。
- 从材料库或材料批次选择配方项。
- 新增、复制、排序和删除工艺步骤。
- 从工艺模板创建实验步骤。
- 计划提交后进入待执行状态。
- 实验执行时记录实际时间、现象、参数、异常、图片和附件。

拖拽不是工艺排序的唯一方式，必须同时支持键盘和按钮排序。

### 5.5 电子实验记录本

- 展示待执行、执行中、待检测和已归档实验。
- 自动暂存当前记录并显示保存结果。
- 按步骤记录操作、现象、参数和实际用量。
- 保存过程图片和结果附件。
- 提交、退回、归档和创建修订。
- 导出实验记录。

### 5.6 检测与报告

- 从实验生成检测委托。
- 配置检测项目、单位、标准范围和判定规则。
- 上传图片、PDF、CSV、TXT 等检测文件。
- 检测人员录入结构化检测值并自动判定。
- 独立审核人复核检测结果，录入人与审核人默认不得相同。
- 生成 PDF 报告并关联实验归档。

### 5.7 系统设置

- 用户和角色管理。
- 材料及材料批次管理。
- 项目、实验、单位、文件类别等基础字典。
- 工艺积木和工艺模板管理。

## 6. 后续范围

### V1.1

- 项目文档和数据资产管理。
- 子实验和实验树。
- 临时相册向实验步骤归集。
- Ketcher 化学结构编辑器。
- 外部检测机构协作和受控结果回传。
- Web Push 或企业消息渠道。

### V1.2

- AI 谱图解析。
- 实验知识沉淀与相似实验检索。
- 甘特图、关键路径和资源冲突分析。
- 数据分析与跨实验趋势。

## 7. 业务规则

### 7.1 编号

- 项目编号：`PRJ-{年份}-{6位序号}`。
- 实验编号：`EXP-{年份}-{6位序号}`。
- 检测委托编号：`TST-{年份}-{6位序号}`。
- 报告编号：`RPT-{年份}-{6位序号}`。
- 编号由服务端生成，组织内唯一，不依赖当前数据行数。

### 7.2 时间

- 数据库存储 UTC 时间。
- 默认业务时区为 `Asia/Shanghai`。
- 计划时间可以调整，实际开始和结束时间由服务端校验。
- 归档时间、审计时间和报告生成时间只使用服务端时间。

### 7.3 删除

- 草稿可以删除，但需保留审计事件。
- 已执行、已提交或已归档的实验不得物理删除。
- 材料、模板、项目采用禁用或归档，不因被引用而删除。
- 文件删除先解除业务引用，再按保留策略异步清理对象。

### 7.4 数据判定

- 检测值与标准必须使用兼容单位。
- 自动判定规则应保存规则版本和判定输入。
- 系统判定结果允许人工复核，但人工覆盖必须填写原因。

## 8. MVP 完成标准

MVP 完成不是页面全部可点击，而是以下路径能够在服务端数据和权限约束下闭环：

1. 管理员创建研究人员、检测人员和项目负责人。
2. 项目负责人创建项目并分配研究人员。
3. 研究人员创建实验计划、配方和步骤。
4. 研究人员执行实验并上传图片。
5. 研究人员创建检测委托，检测人员录入结果，独立审核人完成复核。
6. 系统完成结构化判定和 PDF 报告生成。
7. 项目负责人归档实验。
8. 管理员能从审计日志追溯关键操作。

每一步都必须有成功、校验失败、权限不足和并发冲突测试。

## 9. 待业务确认

- 项目负责人是否必须复核每个实验归档。
- 归档修订是否需要电子签名或双人复核。
- 材料库存是否属于本系统范围，还是只维护材料主数据和批次。
- 检测标准是项目级、材料级还是组织级。
- 浏览器关闭后的提醒渠道。
- 数据和文件的法定或内部保留年限。
