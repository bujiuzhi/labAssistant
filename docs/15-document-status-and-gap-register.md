# 文档状态与实现差异台账

## 1. 目的

本台账解决两个问题：一是让读者快速识别当前可运行能力；二是避免把架构规划、接口草案或未来数据模型误判为已实现功能。基线为 `dev` 分支提交 `fac2e91`，更新日期为 2026-07-27。

判定规则：源码、Django Migration、自动化测试和运行配置证明“已实现”；仅存在于专题设计文档中的内容标注为“规划/参考”。

## 5. 维护动作

每次功能变更按以下顺序维护文档：

1. 先补充或修改 Migration、接口、权限和自动化测试。
2. 更新 `14` 的实现结构、字段/API 映射和测试映射。
3. 若范围、架构或部署边界变化，更新 `13`。
4. 在本台账中将对应规划项改为“已实现基线”或补充剩余缺口。
5. 追加 `00` 的变更记录；涉及重大取舍时新增 ADR。
