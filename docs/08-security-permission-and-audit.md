# 安全、权限与审计规范

## 1. 安全边界

系统假设部署在组织受控网络或受保护的公网入口，但仍按零信任请求处理：每次请求都校验会话、组织范围、动作权限和对象范围。前端菜单、按钮禁用和路由守卫只改善体验，不构成授权。

## 2. 身份认证

- 使用 Django Session 认证，不在浏览器持久化访问令牌。
- Session Cookie 必须启用 `HttpOnly`、`Secure` 和合适的 `SameSite`；生产环境限制 Cookie 域和路径。CSRF Cookie 可供前端读取，但不包含认证凭据。
- 所有状态变更接口校验 CSRF。
- 登录成功、权限变化和密码修改后轮换会话 ID。
- 密码使用 Argon2id；密码策略和单点登录接入作为部署配置。
- 连续登录失败触发分级限流和短时锁定，不能通过错误提示判断账号是否存在。
- 管理员和具备归档、审核权限的用户应启用多因素认证；MVP 可先在组织策略中强制。

## 3. 角色模型

系统基线包含四类业务角色：

- 研究人员：创建和执行本人或参与项目的实验。
- 检测人员：处理被指派的检测委托、录入结果。
- 项目负责人：管理负责项目、成员、实验审核和项目完成。
- 系统管理员：管理组织内用户、角色、基础资料和审计查询。

权限以细粒度权限码授予，角色只是权限集合。平台超级管理员与组织管理员分离，超级管理员不默认读取组织业务正文。

## 4. 权限矩阵

符号：`✓` 允许；`范围` 表示仅本人、被指派或参与项目；`—` 默认不允许。

| 操作 | 研究人员 | 检测人员 | 项目负责人 | 系统管理员 |
|---|---:|---:|---:|---:|
| 查看项目 | 范围 | 范围 | 范围 | ✓ |
| 创建项目 | — | — | ✓ | ✓ |
| 更新项目 | — | — | 负责项目 | ✓ |
| 管理项目成员 | — | — | 负责项目 | ✓ |
| 创建实验 | 参与项目 | — | 负责项目 | ✓ |
| 编辑实验计划 | 本人草稿 | — | 负责项目 | ✓ |
| 提交实验计划 | 本人草稿 | — | 负责项目 | ✓ |
| 执行实验/编辑 ELN | 本人或被分配 | — | 负责项目 | ✓ |
| 提交 ELN | 记录人 | — | 负责项目 | — |
| 退回/归档 ELN | — | — | 负责项目 | 授权后 |
| 创建检测委托 | 参与实验 | — | 负责项目 | ✓ |
| 接收检测任务 | — | 被指派 | — | ✓ |
| 录入检测结果 | — | 被指派 | — | 授权后 |
| 审核检测结果 | — | 独立审核人 | 负责项目 | 授权后 |
| 生成报告 | 范围 | 范围 | 负责项目 | ✓ |
| 管理材料/模板/标准 | 查看 | 查看 | 查看 | ✓ |
| 管理用户和角色 | — | — | — | ✓ |
| 查询审计日志 | 本人关键事件 | 本人关键事件 | 负责项目 | ✓ |

检测结果录入人与审核人不得为同一用户；如组织规模无法满足，必须由配置例外并写入审计。

项目编辑字段包括项目名称、项目类型、项目经理、计划开始与结束日期、人员组成、研发目标和里程碑。
超级管理员与项目负责人具备编辑权限；研究人员和检测人员只读。草稿、待开始、进行中、有风险和暂停状态可编辑，
已完成与已归档状态只读。成员变更还必须具备 `project.manage_members` 权限。

当前 ELN 权限码为 `experiment.view`、`experiment.view_all`、`experiment.create`、
`experiment.update`、`experiment.execute`。超级管理员和项目负责人拥有全部五项；研究人员拥有除
`view_all` 外的四项，并由实验负责人/参与人对象范围继续收敛；检测人员只有 `experiment.view`。
`completed` 状态禁止记录更新，状态迁移和写入均校验 `If-Match` 版本。

## 5. 对象级数据范围

对象访问由以下顺序判定：

1. 用户有效且属于当前组织。
2. 角色具有动作权限码。
3. 对象 `organization_id` 与会话组织一致。
4. 用户满足对象范围：项目负责人、项目成员、实验负责人、实验参与人、ELN 记录人或检测指派人。
5. 对象状态允许该动作。

不存在、跨组织和无对象范围的资源统一返回 404，减少资源枚举；已知对象但动作不允许可返回 403。所有列表必须在数据库查询阶段应用范围过滤，不能先查全量再由 Python 过滤。

## 6. 关键业务保护

- 已发布工艺模板和检测标准不可原位修改。
- 已提交 ELN 通过修订和退回继续，不覆盖历史快照。
- 已审核检测结果通过作废和重新录入纠正。
- 项目、实验和报告归档后默认只读。
- 完成、归档、作废、成员移除和权限变更需要二次确认并写审计。
- 并发更新使用版本校验；冲突时不允许后写覆盖前写。
- 报告必须记录输入快照和模板版本，保证可复现。

## 7. 输入、输出与文件安全

- 所有输入执行长度、类型、枚举、引用和业务规则校验。
- 富文本如后续引入，服务端按白名单清洗；MVP 优先使用纯文本或结构化字段。
- 数据导出防止公式注入，对以 `= + - @` 开头的单元格做安全处理。
- 文件名不参与对象存储路径拼接；对象键由服务端生成。
- 上传文件校验大小、MIME、扩展名和摘要，并进入病毒扫描流程。
- 下载地址短时有效且绑定组织和文件权限。
- SVG、HTML、脚本和可执行文件默认拒绝；业务确需时采用下载附件方式，不在同源域内直接渲染。
- HTTP 响应启用 CSP、HSTS、`X-Content-Type-Options`、合适的 Referrer Policy 和点击劫持保护。

## 8. 审计事件

以下事件必须记录成功、拒绝或失败结果：

| 事件域 | 必审计事件 |
|---|---|
| 认证 | 登录成功/失败、注销、会话失效、密码修改 |
| 用户权限 | 用户启停、角色分配、权限变更 |
| 项目 | 创建、状态变更、成员增删、负责人变更 |
| 实验 | 创建、计划提交、开始、完成、取消 |
| ELN | 保存冲突、提交、退回、归档、修订查看 |
| 检测 | 委托提交、指派、结果录入、审核、作废 |
| 文件 | 上传确认、拒绝、下载授权、关联、解除关联 |
| 报告 | 发起、生成成功/失败、下载、作废 |
| 系统 | 配置变更、批量导出、审计查询与导出 |

审计内容包括请求编号、组织、操作者、动作、资源、时间、结果和必要的脱敏差异。密码、Cookie、完整文件地址和敏感实验正文不得进入审计日志。

## 9. 数据保护

- 传输全程 TLS；数据库、备份和对象存储启用静态加密。
- 密钥和密码由部署环境的 Secret 管理，不写入代码、镜像、日志或 `.env.example`。
- 生产数据不直接复制到开发环境；测试数据应脱敏或合成。
- 备份应加密、限制访问，并定期执行恢复演练。
- 数据保留、导出和删除遵守组织制度；ELN、检测结果、报告和审计日志不得由普通管理员任意物理删除。

## 10. 安全验证

每个版本至少验证：

- 四角色和对象范围的正向、越权和跨组织测试。
- CSRF、会话固定、Cookie 属性和登录限流。
- IDOR、批量赋值、文件类型绕过、下载越权和公式注入。
- 依赖漏洞、镜像漏洞和密钥泄露扫描。
- 生产配置中调试模式、默认密码、公开对象桶和宽松 CORS 均为关闭状态。

高风险问题在上线前关闭；无法立即关闭的风险必须有负责人、影响范围、补偿控制和截止日期。
