# 前端技术规范

## 1. 技术基线

前端采用 Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router 和 ECharts，包管理器统一使用 pnpm。版本基线及升级原则见[系统架构设计](02-system-architecture.md)。

浏览器端只负责展示、交互和可恢复的草稿状态，不承担权限判定、业务编号生成、状态机推进或审计证据生成。

## 2. 目录与模块

建议实现目录如下：

```text
frontend/
├── src/
│   ├── api/                 # 生成的接口客户端与请求适配器
│   ├── assets/              # 全局样式和静态资源
│   ├── components/          # 跨业务通用组件
│   ├── composables/         # 可复用组合式逻辑
│   ├── layouts/             # 工作台与空白布局
│   ├── modules/             # 按业务域组织页面、组件和局部状态
│   │   ├── projects/
│   │   ├── experiments/
│   │   ├── testing/
│   │   ├── materials/
│   │   └── system/
│   ├── router/
│   ├── stores/              # 会话、偏好、字典等全局状态
│   ├── types/               # 前端补充类型
│   ├── utils/
│   ├── App.vue
│   └── main.ts
├── tests/
│   ├── unit/
│   └── e2e/
└── vite.config.ts
```

页面使用 `.vue` 单文件组件和 `<script setup lang="ts">`。业务模块不得反向依赖页面布局；跨模块复用必须通过 `components`、`composables` 或明确的公共类型完成。

## 3. 路由与访问控制

- 路由按业务模块懒加载，路由名称和权限代码使用稳定英文标识。
- 登录页先通过 `/api/v1/auth/csrf` 获取 CSRF 令牌；登录态通过 `/api/v1/auth/session` 恢复，不从本地令牌推断。
- 路由元信息声明 `requiredPermissions`，前端用于导航和体验控制。
- `/system/users` 声明 `requiresSuperAdmin`，仅超级管理员显示导航并允许进入；后端仍执行最终权限校验。
- 后端 401 响应引导重新登录；403 显示无权限页面，不循环跳转。
- 项目、实验、检测等页面使用 UUID 作为路由参数，业务编号只用于展示和搜索。
- 筛选、排序和分页参数写入 URL 查询参数。

## 4. 状态管理

Pinia 仅保存跨页面的客户端状态：

- `sessionStore`：当前用户、角色摘要、权限码和会话状态。
- `preferenceStore`：主题、语言、导航折叠和表格密度。
- `dictionaryStore`：稳定字典和单位缓存，带版本号和过期时间。
- `tabStore`：已打开路由标签及恢复信息。

项目、实验、检测单据等服务端数据由模块级 composable 管理，不复制进多个全局 store。请求取消、竞态和缓存失效应封装在数据访问层。

敏感信息、权限快照和实验正文不得写入 `localStorage`。只允许保存无敏感性的界面偏好；自动保存草稿应提交后端草稿接口。

## 5. 接口访问

接口类型以 [OpenAPI 契约](../contracts/openapi.yaml)生成，禁止手工维护重复的请求/响应类型。请求适配器统一处理：

- 基础路径、JSON 序列化和请求超时。
- Session Cookie 和 CSRF 请求头。
- `X-Request-ID` 透传。
- 标准错误体解析。
- 401、403、409、412、422 和 429 的统一分流。
- `ETag` 保存和 `If-Match` 并发控制。

所有写请求在交互层防重复提交；创建类请求生成 `Idempotency-Key`。前端不得通过重试非幂等请求掩盖网络错误。

## 6. 组件规则

- 业务组件名称表达领域含义，例如 `ExperimentStatusTag`，不使用 `InfoBox1` 等无语义命名。
- 公共组件的 Props、Emits 和暴露方法必须有 TypeScript 类型。
- 复杂表格的列定义与筛选模型放入业务模块，不沉淀为无法维护的万能表格。
- 金额、数量、日期、单位和状态统一通过格式化工具呈现。
- 输入数量采用字符串承接用户输入，提交前使用十进制定点规则转换，避免浮点精度造成展示和保存不一致。
- ECharts 配置封装主题、空态、缩放和销毁逻辑，页面仅提供业务数据映射。

## 7. 表单与草稿

表单分为草稿校验和提交校验：

1. 草稿校验只检查类型、长度和引用对象有效性。
2. 提交校验检查必填字段、状态前置条件和跨字段业务规则。
3. 前端校验用于即时反馈，后端校验是最终依据。

实验记录自动保存采用去抖策略，默认 30 秒周期并在字段失焦后触发；同一记录只允许一个在途保存请求。每次保存携带记录版本，发生 `412 Precondition Failed` 时停止自动保存并进入冲突处理。

## 8. 文件上传

前端采用初始化、直传、确认三阶段流程：

1. 调用初始化接口获取文件 ID 和限时上传地址。
2. 将文件直传对象存储，并展示真实进度。
3. 调用完成接口，等待校验或病毒扫描结果。

浏览器端校验扩展名、大小和数量只用于快速反馈。下载必须使用后端签发的短期地址，页面不得持久保存对象存储内部路径。

## 9. 错误、日志与性能

页面错误必须展示可复制的请求编号。前端日志不得包含密码、Cookie、完整实验记录、文件上传地址或个人敏感信息。

性能预算：

| 指标 | 目标 |
|---|---|
| 首次加载压缩资源 | 不超过 500 KB，图表和富编辑器按需加载 |
| 路由切换可交互 | 缓存命中时 300 ms 内 |
| 普通接口反馈 | 1 秒内显示结果或加载状态 |
| 长列表 | 服务端分页，禁止一次加载全量 |
| 表格渲染 | 100 行常规数据保持流畅 |

## 10. 质量门禁

- ESLint、Prettier 和 TypeScript 严格模式必须通过。
- 核心 composable、格式化工具和权限判断使用 Vitest。
- 项目创建、实验提交、ELN 自动保存与冲突、检测结果录入使用 Playwright 端到端测试。
- 构建不得包含类型错误、未处理 Promise 或生产环境调试日志。
- 合并前执行 `pnpm lint`、`pnpm test` 和 `pnpm build`。
