# 材料实验助手文档中心

## 1. 文档使用规则

`docs/` 是项目的正式文档入口，但不同文档的权威范围不同。阅读或修改前，先按下列优先级判断事实来源：

1. **当前运行事实**：已提交源码、Django Migration、自动化测试与部署配置。
2. **当前设计交付**：[概要设计](13-overview-design.md) 与 [详细设计](14-detailed-design.md)。
3. **业务、体验与质量基线**：需求、原型保真、验收和控制文档。
4. **规划与工程参考**：为后续能力准备的专题规范，不能直接证明功能已上线。

`audit/` 只保留来源、截图、日志和证据；`contracts/openapi.yaml` 是接口设计草案。两者都不替代当前运行事实。

## 3. 推荐阅读路径

- **方案与业务评审**：`00 → 01 → 13 → 14 → 15`。
- **前端开发**：`13 → 14 → 12 → 03 → 04 → 07 → 09`。
- **后端开发**：`13 → 14 → Migration → 05 → 06 → 07 → 08 → 09`。
- **测试与上线**：`13 → 14 → 09 → 10 → 15`。
- **规划新能力**：`01 → 02 → 06 → 07 → 08 → 10`，随后补充 Migration、接口、测试和 `14`。

## 4. 维护规则

- 新增或调整已实现功能，必须同步更新 `13`、`14`、相关测试和 `15`。
- 新增表以 Django Migration 为唯一物理结构来源；`06` 只维护业务语义与规划字段。
- 新增接口以路由、视图和测试为当前事实；OpenAPI 完成同步后再更新 `07`。
- 原型页修改时更新 `12`；重大取舍记录到 `00` 的 ADR 或变更记录。
- 不删除历史专题文档；功能未实现时在 `15` 中明确标记，避免出现双重事实来源。
